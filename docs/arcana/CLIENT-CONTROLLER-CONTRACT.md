# Contrato previo del controlador/metadata de cliente

11 octubre 2026 · A30/A32. Sexto bloque de UI-CONTRACT: recuperar comandos antes de renderizar saldos definitivos, sin economía o engine en React.

`ClientGateway` es puerto para datos/operaciones de autoridad; cliente HTTP lo implementa. `GameController` sin React mantiene estado de carga/envío/recuperación/listo/error, snapshot SQL, contenido público y receipt confirmado. Suscripción de estado para React, sin frame loop o cálculo de daño/recompensa. Keys de nuevas intenciones provienen de función inyectada (browser crypto para uso normal).

Metadata IndexedDB en namespace ARCANA distinto del histórico, solo playerId/kind/key/request/versiones y última key reconocida. Ningún saldo, copy, seed o token se importa como económico confiable. `claim` reserva un slot de intención por jugador en tx de IndexedDB, sin sobrescribir el de otra pestaña. Guardar antes de enviar POST; fallo de metadata no permite emitir gasto. Validar esquema de metadata antes de convertir/recuperar. `finish` con key coincidente marca confirmación/rechazo y limpia slot en tx; nunca borra otra operación. Una respuesta confirmada se presenta después de reconocer metadata; fallo en ese reconocimiento conserva recuperación pendiente.

Carga: consultar estado/session propietario → metadata de ese jugador → si pendiente, consultar receipt antes de saldos definitivos. Receipt existente: mismo resultado, finish, presentar sin nuevo POST/random. 404: reenviar misma intención/key/versiones y respetar revisión/config del servidor. Error/transitorio/UNKNOWN_COMMIT/JSON inválido mantiene intención y exige recuperar; error definitivo 4xx de un comando libera intención como rechazada, luego sincroniza estado/config para nueva confirmación. No emitir retries con otra key, ni aplicar metadata de otro jugador al cambiar sesión.

Otro controlador/pestaña puede completar el mismo receipt; finish de key ya reconocida es idempotente. Si hay otra intención posterior se rechaza limpieza de key antigua. Cambiar idioma/vista/reproducción no emite comandos. Ausencia/config offline no invalida recuperación de receipt anterior; mostrar error/config pendiente junto a resultado confirmado según datos disponibles. HTTP/metadata fallidos no celebran premio ni muestran saldo inventado. Estado previo de UI no se persiste como autoridad.
